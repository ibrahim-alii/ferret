# Module 1: Ingestion

Ref: PRD Sections 4, 5, 9, 10 (module 1).

## Scope

Given an arxiv ID, fetch metadata/abstract, download and parse the source (arxiv HTML preferred, PDF fallback), filter out low-signal sections, produce parent/child chunks, embed the **child** chunks (dense via voyage-4-lite), write chunk records to SQLite (parents included, embedded child vectors handed to module 2 for upsert), and upsert child vectors to Qdrant via module 2. Parent sections are stored in SQLite only and are never embedded. Sparse vectors are generated by module 2 (not here). Exposes a single async entrypoint usable by both the Deep Dive flow (module 4) and Ask's corrective-ingestion step (module 3).

**Parsing (HTML-first, PDF fallback)**: when `ARXIV_PREFER_HTML=true`, fetch arxiv's HTML rendering (`arxiv.org/html/{id}`) and use its section/heading structure, which is reliable for TeX/LaTeX submissions since Dec 2023. Fall back to PyMuPDF on the PDF (font-size/boldness heuristics) for older papers, PDF-only submissions, or failed HTML conversions. Both paths return an ordered list of `(section_name, text)`.

**Section filtering**: after parsing, drop sections that add retrieval noise and bloat vector count without contributing to answerable content. Sections to drop by default (configurable via env/config):
- References / Bibliography
- Acknowledgements / Funding
- Appendix (configurable: some papers have substantive appendices, others just extended tables)
- Author contributions
- Conflict of interest statements
- Sections that are purely lists of equations with no prose (heuristic: text length < threshold after stripping LaTeX)

Sections to always keep: Abstract, Introduction, Related Work, Background, Methods / Methodology, Experiments, Results, Discussion, Conclusion, Limitations.

This reduces chunk count per paper by roughly 20-40%, lowering Qdrant vector usage, embedding API calls, and retrieval noise from citation noise ("Smith et al. [42] showed...") polluting semantic search.

## Dependencies / Contracts

- Depends on module 2's Qdrant upsert interface (`upsert_chunks`). Passes **child** chunks only as `ChunkVector = {chunk_id, paper_id, section_name, chunk_type, dense_vector, text}`; module 2 derives the sparse vector from `text` and owns the collection schema (dense + sparse named vectors, payload `{chunk_id, paper_id, section_name, chunk_type}`). Parent chunks are written to SQLite but never sent to module 2.
- Owns the SQLite schema for `papers` and `chunks` tables (PRD Section 4), and is the sole writer of those tables. Other modules read these tables; changes to column names/types must be flagged.
- Output contract: `ingest_paper(arxiv_id: str) -> PaperRecord` where `PaperRecord` includes `arxiv_id`, `ingestion_status`, `title`, `abstract`. Must be idempotent: calling on an already-`full` paper is a no-op that returns the existing record.

## Implementation Tasks

1. SQLAlchemy (async) models for `papers` and `chunks` (PRD Section 4 columns)
2. arxiv client: `fetch_metadata(arxiv_id)`, `fetch_html(arxiv_id)`, `download_pdf(pdf_url)` (async, httpx, sends `ARXIV_USER_AGENT`)
3. Parser (HTML-first): `parse(arxiv_id)` uses arxiv HTML section structure when available, falls back to PyMuPDF font-size/boldness heuristics on the PDF; both return an ordered list of `(section_name, text)`
4. Section filter: configurable `SECTION_DROP_LIST` applied after parsing, before chunking. Logged at debug level so dropped sections are visible during development.
5. Chunker: parent chunks per surviving section (+ abstract/metadata parent), child chunks via `CHILD_CHUNK_TOKENS`/`CHILD_CHUNK_OVERLAP`. Parents are written to SQLite only; children are the retrieval units.
6. Embedding client wrapper: voyage-4-lite dense embedding of **child** chunks only, batched into a few large requests, bounded by `VOYAGE_MAX_CONCURRENCY` with retry/backoff (parents are not embedded; sparse is module 2's job)
7. `ingest_paper(arxiv_id)`: orchestrates fetch (concurrent metadata + download) -> parse -> filter -> chunk -> embed children -> SQLite write (papers + parent + child rows) -> module 2 upsert of child `ChunkVector`s -> status update. Idempotent for already-`full` papers.
8. Error handling: parse failure on both HTML and PDF degrades to `abstract_only`, not a hard failure
